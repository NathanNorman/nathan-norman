The business

What DatPaq sells

DatPaq bundles 17 utility APIs (DNS, WHOIS, IP lookup, sample data, screenshots, time conversion, and more) behind a single API key and a single monthly bill. Three surfaces reach the same catalog: REST for apps, a Go CLI for terminals and CI, and a hosted MCP server for AI agents in Cursor, Claude, and similar tools.

Root cause

Where the surfaces diverge

Clients and docs point at canonical paths. Production serves some of them and silently omits others. Undocumented aliases (like /dns-lookup) work over REST only. The CLI adds a second layer of drift on MX Lookup parameter names and POST paths.

Evidence

DNS: the canonical path fails

The CLI dry-run confirms it calls the documented URL. Production rejects it. An undocumented alias succeeds.

GET /api/v1/dns?domain=datpaq.com&type=A → 404 {"error":"Service not found","service":"dns"} GET /api/v1/dns-lookup?domain=datpaq.com&type=A → 200 [{"domain":"datpaq.com","records":{"A":["159.203.149.223"]}}]

MX: REST works, CLI does not

GET /api/v1/mx-lookup?domains=gmail.com → 200 OK datpaq mx-lookup get --domain gmail.com → 400 'domains' must be a string or array of strings

Business impact

If unaddressed

  • Agent/CLI marketing claims fail smoke tests
  • Support tickets for "API broken" when docs are technically correct
  • OpenAPI and llms.txt train distrust in the catalog
  • Enterprise evals that run CLI checks fail immediately
  • Dashboard Execute Fetch may break on Convert Time

If fixed

  • MCP + CLI become real differentiators vs RapidAPI-style catalogs
  • First-run success matches the "agent-ready" pitch
  • Contract tests prevent future route drift
  • Dashboard remains the strongest DX surface
  • Positioning holds: one key, every API, every surface

Verdict

Recommended posture

Ship-ready today for developers calling JSON utilities over REST or MCP: WHOIS, IP intel, sample data, unit conversion, profanity, domain lookup, time APIs, and most of the catalog.

Not ship-ready for the claim that all three surfaces work uniformly. DNS is down on CLI and MCP despite being prominently marketed. MX CLI is broken end to end. Several OpenAPI paths 404 in production.

Treat DatPaq as a strong beta with excellent positioning. The broken items are concentrated (route registration, CLI parameter mapping, contract testing). They are fixable without re-architecting the product. Fix P0 before scaling acquisition among agent-first and CLI-first audiences.
